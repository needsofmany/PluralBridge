Synthetic Data Generator

Building and testing PluralBridge against the diversity of real-world plural structures requires examples that are reproducible, inspectable, and safe to share.

Our work with Joshua Reid's open-source plural-synthetic generator provides synthetic examples for developing, testing, and refining the PluralBridge data model.

Why synthetic data matters

Plural systems can have very different internal structures. A single flat list of members or a simple parent-child hierarchy cannot adequately represent every configuration.

Synthetic data allows developers to examine these structures without exposing anyone's private information. Each generated example provides a repeatable test case that can be reviewed, imported, and compared against expected behavior.

These examples help us identify assumptions in application logic, database relationships, importers, and user interfaces before those assumptions affect real users.

The canonical models

PluralBridge has developed eleven canonical models to exercise different ways plural structures can be organized and related.

These models cover configurations involving Systems, Groups, Places, Members, and relationships among them. A System is not required to be the root of every structure.

The examples help validate structural relationships, placements, memberships, and the separation between how a plural structure is organized and who has permission to access or modify its information.

The generator provides consistent input data, allowing us to test behavior across increasingly complex configurations while keeping the examples publicly shareable.

Example 012: An important architectural discovery

During our collaboration, Joshua proposed an additional example that challenged assumptions in the existing PluralBridge design.

Example 012 prompted a broader examination of how the database represents structures whose top-level anchors may be Systems, Groups, or Places.

That investigation exposed technical debt and helped motivate changes to the database architecture, including the handling of object placements, structural relationships, and navigation context.

The request proved considerably more valuable than we initially anticipated. It provided a concrete test of architectural assumptions and a useful direction for the continuing development of the canonical models.

How we use the generator

  • Model validation: Test different combinations of Systems, Groups, Places, Members, and relationships.
  • Importer testing: Check that generated structures are translated into the intended PluralBridge records.
  • Database development: Exercise structural memberships, object placements, and relationship representations.
  • UI development: Provide reproducible examples for navigation and display of simple and complex plural structures.
  • Regression testing: Reuse known examples to detect changes in expected behavior as the application evolves.
